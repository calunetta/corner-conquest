## Plan deviations (both reviewed and accepted)
1. **`TileDecorationEditor.defaultElements.map.ts` split into `.map.ts` (view-model derivation: `DEFAULT_ELEMENT_ROWS`, `toIslandTileSlotsDraft`, `toSlotsForRow`, `getResourceSlotDefs`/`setResourceSlotDefs`) + `.defaultElements.edit.map.ts` (anchored-style math: `toAnchoredStyleFromPointer`, `nudgeAnchoredStyle`, `clampAnchoredOffsetPercent`, the `applyXToDraft` family)** — not in plan.md's File plan as two files. Accepted: each half is a real, distinct responsibility (query vs. mutation) per `component-architecture`'s "one responsibility per file" and the 150-line budget; plan.md's own Contracts block already grouped these two concerns as logically separate (view-model builders vs. pure edit-math), so the split follows the plan's own boundary, it just wasn't named as two files in the File plan table. No behavior or contract changed; both files are owned by implementer-a as the one planned file was. Not a defect.
2. **`src/modules/map/index.ts` barrel also re-exports `CORNER_TRANSFORMS` and `toTileResourcesViewModel`**, beyond the File plan's literal enumeration (plan.md:66). Checked against the Contracts block: `CORNER_TRANSFORMS[cornerId]` is explicitly required by `DefaultElementSlotViewModel.transform`'s doc comment (plan.md:159) and `toTileResourcesViewModel` is explicitly required by `toSlotsForRow`'s resourceSlots branch (plan.md:178) — both are pre-existing exports the Contracts always needed, just missing from the File plan's one enumerated list. This is a plan-authoring gap, not an implementer deviation from intent; the code is correct and necessary (without it, `TileDecorationEditor.defaultElements.map.ts` would need a disallowed deep import past the module boundary). **Plan.md's File plan row for `src/modules/map/index.ts` should be amended to list these two exports**, so the written contract matches what was actually (correctly) built — doc nit, not a defect, no action needed before merging this phase.
