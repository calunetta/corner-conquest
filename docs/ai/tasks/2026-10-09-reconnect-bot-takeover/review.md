## Plan adherence
- `handleSeatReclaim` (`player-reclaim.service.ts`): transaction finds the seat by `playerId` + `isVacant`; immediate flip off-turn, `reclaimRequested = true` on-turn; no-op (`false`, no write) when not found. Matches plan.md's Contracts in substance. **Deviation, reasonable and disclosed:** return type is `Promise<boolean>` instead of the plan's `Promise<void>`, because the original `Promise<void>` design (silently resolving on both success and no-op) is exactly what let a failed reclaim still navigate the player into the match — a real bug caught in cross-review and fixed by making failure observable to the caller. This is a correct improvement on the plan's original contract, not a regression.
- `applyDeferredReclaim` / `handleEndTurn` (`player-turn.reducer.ts`): checks the outgoing player before rotation, flips `isBot`/`isVacant`/`reclaimRequested`, logs `"<name> has reclaimed their seat."` — byte-for-byte what plan.md's Contracts specified. Five new tests cover the exact timing (applies exactly at that player's turn end, not another's; survives a full intervening turn; ignores a `reclaimRequested` flag on a non-vacant seat; leaves a converted seat alone with no pending reclaim).
- `subscribeToVacantSeat`, `Lobby.hook.ts`'s `vacantMatch`/`isReclaiming`/`onReclaimSeat`, `Lobby.types.ts`, `RejoinMatchPanel` (all files): match plan.md's Contracts and File plan rows.
- **`CreateGameDialog` gating** (the round-1 finding from Phase 2's plan review): present and doubly defended — `Lobby.hook.ts` resets `isCreateDialogOpen` to `false` the moment `vacantMatch` becomes set, and `Lobby.tsx` additionally forces `open={model.isCreateDialogOpen && !model.vacantMatch}`. Covered by `Lobby.test.tsx`'s "keeps the Create Game dialog closed even when it was requested open."
- **Lobby restriction hides create/join UI and the open-games list**: confirmed in `Lobby.tsx` (the `!model.vacantMatch` branch wraps both columns) and tested (`Lobby.test.tsx`: "hides the create/join UI and the list of open games").
- Preview states match plan.md exactly: Default and Reclaiming (disabled).
- Acceptance criteria from plan.md's Goal section: the first five are fully met (seat conversion on exit, staleness-triggered conversion, unchanged pre-game behavior, delete-on-zero-humans, lobby restriction to the player's own match). The sixth — "If it is currently that seat's (bot) turn, the handoff waits until the bot's turn finishes... no mid-turn interruption" — is correctly implemented in the **data model** (see `applyDeferredReclaim` above) but is **not fully honored in the UI**; see Finding 1.

| 1 | `src/modules/game-board/game-board.engine.hook.ts:83-85` (`isMyTurn`) | **Real bug, previously unreachable, now reachable by this feature.** `isMyTurn` is `currentPlayer.id === localPlayer.id`, with no check of `currentPlayer.isBot`. Before this task, a human's `playerId` could never equal a bot seat's `playerId` (bots are only ever created at setup with their own synthetic identity), so this was safe. Now, a deferred reclaim (`handleSeatReclaim` sets `reclaimRequested: true` but leaves `isBot: true` until `handleEndTurn` applies the flip) creates exactly that situation: `Lobby.hook.ts`'s `handleReclaimSeat` calls `onJoinGame` as soon as `handleSeatReclaim` resolves `true` — which it does for *both* the immediate-flip and the deferred branches — so a player who reclaims **during their own seat's bot turn** is routed straight into `GameBoard` while `isBot` is still `true` on their seat. There, `isMyTurn` evaluates `true` (seat ids match) and `ActionsPanel`/`MobileActionsBar` (gated only on `isMyTurn`, confirmed by grep — no `isBot` check anywhere in that chain) render full live controls, while the session driver's bot-turn effect (`game-board.engine.hook.ts:141-152`, unchanged, still gated on `isBot` alone) is independently timing out and about to call `takeBotTurn` for the same turn. This contradicts the plan's explicit acceptance criterion ("no mid-turn interruption") and risks a human action racing the bot's plain (non-transactional) `setDoc`/`takeBotTurn` write. **Untested**: all reclaim tests stop at the reducer/service layer (`reclaimRequested` is set, `handleEndTurn` applies it later) or test `Lobby.hook`'s navigation decision in isolation; none renders `GameBoard`/`ActionsPanel` with a current player whose own seat is `isBot: true`.
