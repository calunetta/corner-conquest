## Re-review note (amended contract)
`plan.md`'s markup contract was amended by architect-a to make the Tooltip removal the approved contract (`plan.md:135`), reason: Radix `TooltipTrigger`'s `data-state` overwrites the `Switch`'s own `data-state`, which the `Switch` primitive uses for its track color. Verified the root cause directly in `node_modules`, independent of the plan's claim: `node_modules/@radix-ui/react-switch/dist/index.js:80-90` — `Switch.Root` sets `"data-state": getState(checked)` *then* spreads `...switchProps` **after** it, so any `data-state` arriving via props (e.g. merged in by an ancestor's `asChild` Slot) silently overwrites the Switch's own checked/unchecked attribute. `node_modules/@radix-ui/react-tooltip/dist/index.js:209-227` — `TooltipTrigger` does set `"data-state": context.stateAttribute` ("open"/"closed") on the element it wraps via `asChild`. The conflict is real, not just asserted. Shipped `GameBoardHeader.tsx` has no `Tooltip`/`TooltipTrigger`/`TooltipContent` import or usage anywhere (confirmed by Read and grep), matching the amended contract exactly. `progress.md:37,39` records the original finding (implementer-b, via preview-a's headless screenshot showing a transparent track in both states) and architect-a's contract amendment. Original finding #1 from my prior CHANGES-REQUESTED pass is resolved by this amendment; findings #2 (below, `ImageIcon`) was already non-blocking and is now also part of the approved contract (`plan.md:149`).

All checks below were already run in the prior pass against the same shipped diff (contract text changed, code did not); re-confirmed current.
