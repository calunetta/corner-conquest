## Why this tier
- Touches data (`src/lib/types/monsters.ts:1-17`), game-rule reducers (`src/modules/game-rules/monster-catalog.ts:4-67`, `src/modules/game-rules/map-generation.ts:1-40`), rendering (`src/modules/map/components/AnimatedMonster/`), combat UI (`src/modules/combat/components/MonsterCombatDialog/`, `MonsterSelectionDialog/`), and a new testbed tool + API route — 4+ modules, both logic and view layers.
- Gameplay signal: yes. Spawn rules change from "1 fixed monster per level 1-4" to "random pick among same-level candidates" and "random pick among boss-tagged candidates for the center tile" (`src/modules/game-rules/map-generation.ts:15-24`, `src/modules/game-rules/monster-catalog.ts:11-67`).
- Visible UI signal: yes — new testbed upload tool, and combat must gracefully skip the attack animation when a monster has no `attack.gif`.
- Data/type signal: `MonsterName` moves from a hand-maintained enum (`Lancer | Bear | Ogre | Minotaur`) to a generated string-literal union, emitted into a generated catalog file alongside the parsed monster data — keeps `game-rules` reducers pure (no filesystem access at game-rule runtime; the catalog is static data checked in and regenerated by a script/API route, mirroring the decoration editor's `regenerate-source.ts` pattern at `src/app/api/tile-decoration-editor/images/route.ts`).
- Risk: game-rule reducers and multiplayer-synced spawn logic (`generateIslandTerrain`) are touched — any haiku builder work here must be escalated to sonnet per the L-tier rule.

## Scope
- In:
  - A scanner/generator (script or API-triggered) that reads `public/monster/*.gif`, parses `<name>-lvl<N>-idle.gif` / optional `-attack.gif` / optional `boss-` prefix, and writes a generated catalog file (monster data + a generated `MonsterName` string-literal union type).
  - Rework of `monster-catalog.ts` / `map-generation.ts` spawn logic: random pick among same-level non-boss candidates (replacing the fixed 1:1 level→name map), random pick among boss-tagged candidates for the forced center tile (replacing the hardcoded Minotaur).
  - Combat/rendering: skip the attack animation step when a monster has no `attack.gif`.
  - A new testbed tool to upload idle (required) + attack (optional) sprites for a new monster, triggering catalog regeneration — modeled on the decoration editor's image-upload API route.
  - `docs/architecture/*.md` updates for the new spawn rule and asset convention (docs-sync, mandatory — this changes documented monster spawn behavior).
- Out:
  - Changing combat power-scaling formulas tied to `Monster.level` (level stays a number; only how levels map to names changes).
  - Migrating/removing the old 4 flat sprite files unless they're moved into `public/monster/` as part of adopting the new convention (confirm during planning whether existing sprites are renamed into the new scheme or left as-is and superseded).
  - Any change to Firestore document shape beyond what `Monster`'s type change (name: string vs enum) already requires.

## Open questions
- Resolved with the user: boss selection is random among all boss-tagged candidates; missing attack.gif skips the attack animation; the catalog is a generated static file (not a runtime fs scan) regenerated on upload; `MonsterName` is a generated string-literal union emitted by that generator, not a hand-maintained enum.
- Resolved with the user (2026-10-17): level caps. Non-boss monsters are levels 1–3; boss monsters are levels 1–4. No level 5. A boss-tagged file above level 4, or a non-boss file at level 4, is rejected by the generator with a warning. A level-4 roll with no non-boss level-4 monster falls back to level 3, so ring-1 neighbors of the center get a non-boss level-3 monster and never the Minotaur.
- Resolved with the user (2026-10-17): the four current monsters are permanent seed entries (Lancer lvl1, Bear lvl2, Ogre lvl3, Minotaur lvl4 as boss). Their sprites were copied into `public/monster/` with the new names (`lancer-lvl1-idle.gif`, `boss-minotaur-lvl4-idle.gif`, etc.). The old `public/sprites/<name>_*.gif` files remain until the build phase switches code over.
